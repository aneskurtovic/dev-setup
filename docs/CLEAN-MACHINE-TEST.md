Run this gate in a disposable Windows 11 x64 VM as the intended user. GitHub Actions uses isolated fixtures and does not replace this gate.

For steps 1–5 of the core preset, `tests/sandbox/Start-Sandbox.ps1` runs them unattended in Windows Sandbox against the release `quickstart.ps1` points at; results land in `test-results/sandbox/out`. Sandbox cannot survive a reboot, so the remaining steps and the developer preset still need a VM with snapshots.

1. Snapshot a fresh Windows account without Git or PowerShell 7. Record Windows edition/build and processor architecture. Obtain this repository as a ZIP and extract it; Git must not be needed to obtain setup.
2. In Windows PowerShell 5.1 run `powershell.exe -NoProfile -File .\bootstrap.ps1 -Mode Plan`. Confirm that no software, profiles, or Terminal settings were created.
3. Run `powershell.exe -NoProfile -File .\bootstrap.ps1 -Mode Apply`. Inspect any UAC prompts. If App Installer is unavailable, test both the documented manual App Installer path and the explicit `-RepairWinGet` option on separate snapshots.
4. Open a fresh PowerShell session. Run `pwsh -NoProfile -File .\Setup.ps1 -Mode Doctor -Json`. All four core packages and the workspace must be ready. Authentication remains a separate step.
5. Run `Setup.ps1 -Mode Plan -Json`, then Apply again. Confirm no package installs/upgrades and no changed workspace files. Run `ai-workspace -Preview`, then `ai-workspace` for the three panes, or a registered project's `terminal` action. Agent panes may report missing optional CLIs.
6. Open Terminal, then repeat Plan. If Terminal has modified the managed settings file, this version may report a conservative conflict; retain the report. Do not erase it by resetting configuration. This limitation must be resolved before claiming unattended long-term convergence.
7. Restore the snapshot and repeat with existing PowerShell profiles and commented Terminal settings. Preserve unrelated bytes and verify only the planned values change.
8. Exercise an interrupted download, incompatible existing tool, denied elevation, missing executable after install, and a restart-required installer. Expect a nonzero Apply/Doctor exit, an actionable report, and no automatic reboot.
9. In isolated configuration fixtures, test user edit → reinstall → rollback. Reinstall must refuse drift; rollback must preserve user edits by refusing restoration. Check original files and retained backups.

For the `developer` preset, use a separate fresh snapshot. Run `bootstrap.ps1 -Mode Plan -Preset developer`, then interactive Apply with `-Preset developer`. Verify the selected application list, GitHub login, grouped personal/organization repository choices, `none`, multiple numbers, and ranges. Select two repositories under different owners and confirm clones appear only under `<ProjectRoot>\<owner>\<repo>`. Add a dirty matching clone before rerun and confirm it remains untouched. Add a destination with a different `origin` and confirm Apply reports a conflict without replacing it. After reboot and Ubuntu first launch, rerun Apply and Doctor; Docker Desktop may need additional first-launch setup. Check that `ai-workspace`, `ai-workspace-resume`, and `ai-workspace-agents` open their respective new-session, saved-session, and all-agent views. Verify project `cc`/`cx` shortcuts open one full-size pane with the project name first in the title.

Keep run reports under `%LOCALAPPDATA%\DevSetup\runs`; they contain local paths, so review them before sharing. `TerminalDevSetup` remains the runtime/backup directory for compatibility. Packages are never removed by `Uninstall.ps1`.

This gate has not been run in the development session: Hyper-V is present but VM access was denied by host permissions. ARM64, other OSes, WSL, Docker, unattended reboots, and enterprise-managed installation policies are outside the verified support claim.
